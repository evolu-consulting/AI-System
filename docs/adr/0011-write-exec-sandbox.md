# ADR-0011 · Sandbox ghi + thực thi + container cô lập cho job tự-sửa (P-c)

Trạng thái: **Accepted** 2026-10-13 — người dùng duyệt Q4/Q6/Q7 (spec P-c §10); khuyến nghị điền ở PLAN P-c (backend-lead, 2026-10-13) · Ngày: 2026-10-12 (khung), 2026-10-13 (khuyến nghị) · CR-061, CR-065 · Spec: `docs/specs/P-c-autofix/spec.md` (+ `plan.md` §5 Runtime) · Kế thừa: ADR-0007, ADR-0008, WRK-NFR-02, WRK-BR-07/07a

## Bối cảnh
P-b chỉ cho agent Read/Grep/Glob trên snapshot chỉ-đọc, an toàn nhờ hook WRK-BR-07. P-c (HUB-FR-119, 126…130) cần agent **ghi file và chạy lệnh tự do** (test, build) trên bản sao riêng `work/<job_id>/workspace/`. Hook đường dẫn không đủ cho Bash tự do (HUB-BR-33): phải có container mỗi job. Worker production: WSL2 Ubuntu, systemd user `worker` (WRK-NFR-06, `deploy/ai-worker.service`). Dev hiện chạy Runtime trong container Docker Desktop (`ai-hub-dev-runtime`).

**Kiểm máy dev 2026-10-13 (lệnh chỉ-đọc):** Docker Desktop 29.6.1 (VM `docker-desktop`, cgroup v2, runc, seccomp + cgroupns, 12 CPU, **8 GB RAM cho VM**); `podman` không có trên Windows; WSL 3.0.3, kernel 6.18.54, distro `Ubuntu` có nhưng đang Stopped (không khởi động để kiểm — chưa biết có podman/systemd); không có `runsc`. **Ổ C còn ~5 GB** (ảnh Docker nằm ở C) ⇒ ảnh sandbox phải nhỏ (≤ ~600 MB).

### Cơ chế tool của agent (hệ quả của #1, #4)
Stage tự-sửa: Hub ép `allowed_tools` gốc = `[Read, Grep, Glob]` chỉ cho `sources/` (nếu stage có nguồn) hoặc `[]`; Runtime thêm 4 tool MCP `ws` chạy **bên trong container** qua `exec`: `ws_exec{cmd,timeout_s}`, `ws_read{path,offset?,limit?}`, `ws_write{path,content}`, `ws_edit{path,old_string,new_string,replace_all?}` (tìm/grep = `rg` qua `ws_exec`). Hook WRK-BR-07 **chặn** tool gốc dưới `work/<job_id>/workspace/` và `git/`. Đây là **ngoại lệ thứ hai của HUB-BR-12** (sau `kh_query`) — người dùng duyệt (Q4, 2026-10-13).

## Hệ quả
- Không có container (`RUNTIME_SANDBOX=off` hoặc CLI lỗi) ⇒ job lỗi `container` ⇒ "Cần người quyết" `sandbox_unavailable`; stage tự-sửa không bao giờ chạy với hook thay container (HUB-BR-33, WRK-BR-08).
- Production cần: WSL2 `systemd=true`, `podman` rootless, delegate controller `cpu memory pids` cho user `worker` (cgroup v1 ⇒ trần bị **bỏ qua âm thầm** — Runtime phải tự kiểm lúc khởi động: chạy container thử `--memory`, đọc lại `memory.max`; sai ⇒ coi như `off`). Ghi `PRODUCTION-NOTES` khi BUILD.
- Dev Windows: Runtime dev cần docker CLI + socket + ánh xạ đường dẫn `RUNTIME_SANDBOX_HOST_WORKDIR` (đường `work/` nhìn từ Docker Desktop). Bind mount Windows ⇒ quyền sở hữu file khác production (uid) — rủi ro đã biết, kiểm ở UAT.
- Cập nhật WRK-NFR-02/WRK-BR-08, `sandbox/README.md` khi BUILD.

## Bổ sung (CR-065, 2026-10-12)
Không đổi quyết định hạ tầng; chỉ thêm ràng buộc cho Runtime, không ADR mới.
- **Clone riêng + nhánh:** mỗi job một bản sao riêng (CR-061 D2); nhánh `ai/<run>/<step>`; trượt duyệt ⇒ commit thêm vào cùng nhánh (P-c1: dựng lại nhánh từ commit ghim + bản vá vòng trước, xem #5).
- **Kiểm diff bằng chương trình (WRK-FR-29):** chạy lại test trong container, quét bí mật, allowlist đường dẫn trước khi trả diff; không dùng LLM.
- **Rebase do Runtime:** `main` đổi ⇒ rebase + chạy lại test trong container; xung đột ⇒ "Cần người quyết". (P-c1 diff so với commit **ghim** nên chưa cần rebase — làm ở P-c2 cùng PR.)
- **Chế độ áp (HUB-BR-34):** `pr` / `auto_merge` / `branch_only`. Token provider chỉ ở Hub/Runtime-chương-trình, không vào container. (P-c2.)
- **Giữ:** container mỗi job (HUB-BR-33), cấm ghi `local_path` (HUB-BR-32), Edit/Write + chạy test chỉ trong container.
