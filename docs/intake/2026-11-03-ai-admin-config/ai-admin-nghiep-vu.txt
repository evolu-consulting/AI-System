Nguồ n chu ẩ n về  nghiệp vụ ai-admin. T ổ ng h ợ p t ừ  BA gố c ( ba-admin.md  v0.4), code, spec
con và ADR — BA v0.4 đã lỗ i th ờ i vài chỗ  (SSO, cộ t m ớ i c ủ a user/tenant, app_catalog/gói,
đố i tác), nên tài liệ u này m ớ i là b ả n h ợ p nhấ t. Cấ u trúc: Phần A mô t ả  toàn bộ  nghiệ p vụ
hiệ n hành theo m ả ng; Phần B là h ướ ng đang tri ể n khai (c ả i t ổ  cấ u hình + phân quyề n, CR-

T ổ ng quan ai-admin
Mục đích. Mộ t n ơ i quyế t định tenant nào, nhóm nào, ai đ ượ c dùng gì và dùng bao nhiêu —
đ ổ i hành vi hệ  thố ng mà không cầ n deploy.
Admin lo: danh tính (tenant, user, group, đăng nhậ p, token); phân quyề n (3 vai qu ả n trị,
feature/entitlement/grant); catalog workflow Dify + command dùng chung; quota & chi
phí theo tenant; secret mã hoá; audit + export/import.
Admin KHÔNG lo: chạy workflow, gọi LLM, l ư u hộ i thoại, cấ u hình agent — thuộ c Agent
Hub (nút Test ch ỉ  nh ờ  Hub chạy th ử ).
Bốn khối nền t ả ng: Admin · Agent Hub (điề u phố i agent, Studio, process engine) · Worker
(job, CLI) · Chat App/Extension (ng ườ i dùng cuố i). Trang Quy trình và Nguồ n hi ể n thị trong
admin-web nh ư ng d ữ  liệ u thuộ c schema hub .
Gi ả  định nền: command, workflow, secret, key Dify dùng chung toàn hệ  thố ng; tenant ch ỉ
đ ượ c cấ p quyề n dùng, không t ự  tạo. Admin và Hub chung mộ t Postgres; admin s ở  h ữ u
schema admin .
Actor: platform_admin · tenant_admin · member · Agent Hub (hệ  thố ng, đọc hub_ro ) ·
Builder.
Tenant / công ty
Mục đích. Mỗ i tenant là mộ t công ty khách hàng; mọi user và d ữ  liệ u thuộ c đúng mộ t
tenant. Công ty vậ n hành cũng là tenant platform .
B ả ng admin.tenants : key  (mã công ty, unique), name , active , max_concurrent_sub ,
settings , timezone  (IANA, mặ c định Asia/Ho_Chi_Minh ), process_runs_max ,
profile , default_app , version .

Mục tiêu & bố i c ả nh
Tài liệ u cho độ i phát tri ể n: mô t ả  nghiệ p vụ và ràng buộ c đ ể  hiệ n th ự c việ c c ả i t ổ  cấ u hình
ai-admin. Chi tiế t kỹ  thuậ t nằ m ở  ADR-0033 và spec docs/specs/CR-107 .
Hiện trạng. Các màn cấ u hình ( ứ ng dụng, feature, ng ườ i dùng, nhóm, phân quyề n) nằ m tr ả i
đề u ở  sidebar; muố n cấ u hình mộ t công ty ph ả i nh ả y qua nhiề u màn, mỗ i màn t ự  chọn lại
công ty. Quyề n đọc/ghi đang ẩ n trong khái niệ m "feature" kỹ  thuậ t, khó hi ể u v ớ i ng ườ i vậ n
hành.
Mục tiêu. (1) Gom cấ u hình theo ng ữ  c ả nh công ty (tenant); (2) trình bày quyề n bằ ng ngôn
ng ữ  vai + đọc/ghi; (3) gi ữ  nguyên cách ly tenant và đi ể m chặ n quyề n đang chạy ở  backend.
Mô hình t ổ ng th ể
Ba trục, tách bạch:
Ứ ng dụng gán theo công ty. Mỗ i công ty (tenant) đ ượ c bậ t các ứ ng dụng/gói nghiệ p vụ
cầ n dùng (H ợ p đồ ng, Community, Chat AI…). Bậ t = cấ p quyề n dùng cho công ty đó.
Điều h ướ ng lồng. Sidebar trái ch ỉ  liệ t kê tên công ty + "Thêm công ty". Chọn mộ t công
ty → m ở  workspace bên ph ả i, trong đó có tab: T ổ ng quan · Ứ ng dụng & Gói · Phân quyề n
· Ng ườ i dùng · Chi phí & quota. Danh mục dùng chung (định nghĩa ứ ng dụng, feature)
vẫ n ở  cấ p Nề n t ả ng, tách kh ỏ i công ty.
Quyền 3 tầng. ①  vai hệ  thố ng (toàn admin) · ②  vai theo app (đọc/ghi) · ③  gán ng ườ i
dùng vào vai — chi tiế t ở  mục Phân quyề n.
Phân quyề n — vai theo app
Quyề n chia 3 tầ ng, không trộ n:
1. Vai hệ thống — platform_admin  / tenant_admin  / member . Gán ở  hồ  s ơ  ng ườ i dùng,
quyế t quyề n qu ả n trị. Không nằ m trong màn phân quyề n.
2. Vai theo app — mỗ i vai thuộ c đúng mộ t ứ ng dụng, mang mộ t m ứ c quyề n. Mỗ i app khi
bậ t có sẵ n 3 vai mặ c định; tạo thêm vai tuỳ biế n đ ượ c.
3. Gán ng ườ i dùng vào vai — mộ t ng ườ i có th ể  gi ữ  vai ở  nhiề u app; quyề n th ự c tế  tính
theo t ừ ng app.
